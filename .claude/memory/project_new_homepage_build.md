**Why / gotchas:**
- NEVER write `-webkit-backdrop-filter` (or other manual prefixes) after the standard property: Next's Lightning CSS merges the pair and keeps the LAST one, so Chrome got only the -webkit version and every blur on the site silently failed (found 2026-10-08). Write only the standard property; the build adds prefixes.
- Above-the-fold entrance animations must be CSS (`.hm-rise`), not Motion — Motion-driven hero stayed invisible until hydration, user saw "continuously loading".
- Hero beam = conic gradients in a tall layer; keep the layer only as tall as needed (`max(1000px,100svh)` half-height) — a 4000px layer made big screens slow.
- Logo mark is a PNG (`public/home/logo-mark.png`, pre-sized 3x = 108x111, `unoptimized`): its SVG drop-shadow filters render wrong in Chrome at 36px.
- Next dev image optimizer (/_next/image) can get a request stuck forever (seen: w=96 WebP for the logo); identical requests then queue behind it → page never finishes loading, image missing. Fix = restart dev server; avoid by serving small fixed icons pre-sized + `unoptimized`. Diagnose with curl using Chrome's `Accept: image/avif,image/webp,...` header — plain curl gets PNG and looks fine.
