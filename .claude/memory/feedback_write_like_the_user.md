When drafting anything the user will post or send as themselves (Jira comments, replies to founders, Slack/email messages, status notes), write it in their own voice, as if typed by hand. Not a polished AI write-up.

**Why:** the user (2026-11-19) rejected a structured Jira comment as "looks created by Claude"; they want text that passes as their own, and asked that this apply to every comment/reply from now on.

**How to apply:**
- Keep it short: a one-line opener, a few plain dashes, one or two closing lines. No bold headings, no "Changes made / Status / Open item" sections, no tables.
- Plain everyday wording; first person where natural ("Updated…", "Moved…", "Still need…"). No phrases like "As agreed", "This ensures", "Please note", "I'd be happy to".
- No em dashes; avoid perfectly parallel bullet phrasing and over-explaining reasons.
- Give the text ready to paste, with no wrapper commentary inside it; at most one short line outside it if something needs flagging.

Related: [[no-copy-changes]] (site copy stays verbatim) is a different rule; this one is about text written *for* the user to send.
